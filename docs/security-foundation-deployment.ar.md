# أساس الأمان قبل الحسابات العائلية — نطاق التنفيذ والنشر

هذه المرحلة تصلح نسخة SQLite المرفوعة من Orange Pi وتوفقها مع main. لا تضيف العائلات بعد، ولا تحول محرك قاعدة البيانات. تصميم المساحات والأدوار والدعوات والترحيل موثق في [التصميم التقني](personal-family-technical-design.ar.md).

## السلوك الذي تغير

- `/api/user/sync` يقرأ ملف صاحب الجلسة فقط، ولا ينشئ مستخدمًا أو يغير البريد أو يصدر رمزًا من uid يرسله العميل.
- المعاملات والفواتير تمنع تعارض المعرفات بين المستخدمين على مستوى SQL، وليس الواجهة فقط. التعديل والحذف والقراءة تعود لحساب صاحب الجلسة.
- تسجيل الدخول يصدر جلسات مستقلة لكل جهاز، عشوائية من مصدر تشفيري، بمدة 30 يومًا. قاعدة البيانات تحفظ SHA-256 للرمز فقط. الخروج يلغي جلسة الجهاز، والدخول السريع يدوّر جلسته دون إخراج الأجهزة الأخرى.
- في أول تشغيل للإصدار الجديد، تُلغى الرموز القديمة الموجودة في `users.token` لأن مسار المزامنة السابق كان يكشفها. لم تُحذف الحسابات أو كلمات المرور أو الدفاتر؛ يلزم تسجيل الدخول بكلمة المرور مرة أخرى وإعادة تفعيل الدخول السريع. هذا الإلغاء لا يتكرر في كل إعادة تشغيل.
- SSE يستخدم تذكرة لمدة 30 ثانية وللاستخدام مرة واحدة. التصدير يستخدم ترويسات المصادقة. لا يقبل API الرموز في query string بعد الآن. الروابط القديمة للتصدير والعملاء القديمون يحتاجون تحديث التطبيق.
- الاستيراد يتحقق من كامل الملف، ويعمل داخل transaction واحدة. الافتراضي دمج حسب المعرف، و`mode: replace` خيار صريح في API. تعارض سجل مع مستخدم آخر يرفض الملف بالكامل. التصدير والاستيراد يشملان الفواتير المتكررة؛ الملفات JSON مقروءة وليست مشفرة.
- إدارة المنصة تعرض أعداد المستخدمين والمعاملات والفواتير فقط. البريد الذي كان يمنح صلاحية الأدمن تلقائيًا لم يعد يفعل ذلك. تفعيل شاشة الإحصاءات يحتاج `PLATFORM_ADMIN_UID` مضبوطًا على uid حساب موجود، ولا يمنحه عرض دفاتر الناس أو مسحها.
- الاستيراد التلقائي من JSON القديم معطل في التشغيل العادي. `ENABLE_LEGACY_JSON_MIGRATION=true` إجراء ترحيل قديم استثنائي، ويجب أن يبقى false في الإنتاج الحالي. أُزيل JSON الفارغ من المستودع.
- Docker يستخدم `npm ci` للمحافظة على إصدارات lockfile.

## التحقق

`npm ci` ثم `npm run lint` ثم `npm test`.

اختبارات التكامل تشغل السيرفر المبني فعليًا على قاعدة مؤقتة بمعاملات وإعدادات قديمة، وتتحقق من المحافظة عليها، وإلغاء الرمز القديم مرة واحدة، والجلسات والأجهزة، ومنع الصلاحيات المزورة وتعارض المعرفات، والتحقق من الصفوف، والتراجع الذري حتى عند خطأ SQLite أثناء الكتابة، والتصدير والفواتير، وحدود إدارة المنصة، وتذاكر SSE، وإعادة تشغيل السيرفر. لا تتصل بقاعدة الإنتاج ولا تستخدم بيانات مستخدمين حقيقية.

تشغّل GitHub Actions نفس الفحص على Node.js 22. يوجد تحذير بناء عن حجم حزمة الواجهة، وهو موضوع أداء منفصل.

## قبل أي نشر فعلي

1. مراجعة PR وتأكد نجاح CI ثم دمجه. لا تُشغّل نسخة تجريبية مباشرة على قاعدة الإنتاج أثناء تجربة الترحيل.
2. أخذ SQLite backup متسق عبر `better-sqlite3.backup()` بدل نسخ ملف `.db` وحده وهو يعمل؛ تحقق من سلامة النسخة واحتفظ بنسخة خارج SSD.
3. فحص أعمدة الجداول الفعلية ومقارنتها بنسخة السيرفر. الاختبار يغطي مخطط النسخة المرفوعة، ولا يثبت أن قاعدة الإنتاج تملك كل الأعمدة نفسها؛ CREATE TABLE IF NOT EXISTS لا يضيف أعمدة إلى جدول أقدم.
4. اختبار نسخة احتياطية في مسار مستقل مع الإعدادات نفسها، وخاصة الدخول بكلمات المرور القديمة. إذا توجد حسابات بلا password hash، يلزم مسار استعادة هوية آمن لها قبل إلغاء رموزها؛ لا تعِد فتح sync غير المحمي.
5. إبلاغ المستخدمين بضرورة تسجيل الدخول مجددًا، وتحديث PWA/العميل كي يرسل رمزًا في الترويسة ويطلب تذاكر المزامنة الجديدة. العمليات المحلية المعلقة لم تُحذف من طابور المستخدم عند الخروج.
6. إيقاف الكتابات أثناء التحديث، نشر الإصدار، فحص الدخول والمعاملات والفواتير والتصدير والمزامنة على الجهاز الفعلي، ثم فتح الكتابات.

في Docker الحالي، `DATABASE_PATH=/app/data/albait.db` ومجلد SSD المرتبط يبقيان كما هما. `PLATFORM_ADMIN_UID` اختياري؛ إن لم يُضبط فلا يظهر الأدمن لأي حساب. لا تضع كلمة مرور مستخدم أو session token في Compose أو GitHub.

الرجوع قبل استقبال كتابات جديدة يتم باستعادة نسخة DB السابقة مع إصدار الكود السابق. بعد استقبال كتابات، لا تُعد نسخة DB قديمة فوقها؛ احتفظ بنسخة حديثة وصالح البيانات أولًا. الإصدار القديم يحمل الثغرات الموصوفة، ولذلك الرجوع إليه لا يصلح كحل دائم للنشر العام.

## ما بقي قبل الإطلاق للعامة

لم تُفعّل المساحات العائلية والأدوار والدعوات بعد. لم تُغيّر بيانات المبالغ من REAL إلى وحدات عملة صغرى أو تقسّم إعدادات المستخدم/الدفتر. ما زالت الواجهة القديمة تخزن رموز الجلسات محليًا؛ الانتقال إلى HttpOnly cookies للويب وKeychain/Keystore للجوال، وحماية CSRF المناسبة، من خطوات التنفيذ التالية. ميزة الدخول السريع الحالية لا تُعد تنفيذًا مكتملًا لمصادقة WebAuthn على السيرفر.

كذلك يلزم تحقق البريد واستعادة كلمة المرور وحذف الحساب، وتقييد CORS وضبط CSP والوكيل وحدود الطلبات بحسب بنية HTTPS الفعلية، وتحسين مستخدم حاوية Docker وأذونات مجلد البيانات، واختبارات الجوال والأداء والنسخ والاستعادة. هذه المرحلة لا تمنح التطبيق جاهزية النشر على المتاجر.
