# دفاتر العائلة — التنفيذ والنشر

## المتاح الآن

من أعلى التطبيق اختر «دفتر شخصي» أو «دفاتر العائلة». اختيار العائلة لا يغير الدفتر الشخصي ولا ينقل أي سجل منه. أنشئ عائلة باسم وعملة، أو الصق رمز دعوة لحسابك المسجل. يمكن الانضمام لأكثر من عائلة والتنقل بينها.

- **المالك:** يدير الدفتر والأعضاء والدعوات، ويعيّن مديرًا أو ينقل الملكية لعضو موجود. لا يمكنه حذف عضويته قبل نقل الملكية. لكل عائلة مالك واحد.
- **المدير:** يدير معاملات الدفتر وإعداداته، ويدعو المحررين والمشاهدين ويغيّر أدوارهم أو يزيلهم. لا يغيّر المالك أو المديرين ولا يعيّن مديرًا جديدًا.
- **المحرر:** يقرأ الدفتر، ويضيف معاملات وفواتير، ويعدّل أو يحذف ما أنشأه فقط. لا يدير الأعضاء أو الإعدادات أو الاستيراد.
- **المشاهد:** يقرأ ويصدّر الدفتر فقط.

كل دور يرى الدفتر العائلي وحده، ولا يتيح أي دور عرض الدفتر الشخصي لأي عضو. إدارة المنصة لا تمنح عضوية عائلية تلقائية. جميع الصلاحيات تفحص على السيرفر عند كل طلب؛ إزالة العضو تمنع طلباته التالية فورًا، مع الاحتفاظ بالسجلات المشتركة التي أنشأها.

تُنشأ الدعوات لحساب موجود عبر بريده، وتُربط بمعرفه الدائم. يُعرض الرمز للمدير الذي ينسخه ويشاركه يدويًا مع العضو المقصود، ولا يُرسل بريد أو رسالة تلقائيًا. يعمل الرمز مع الحساب المدعو فقط، ويُخزّن hash في قاعدة البيانات، وينتهي بعد سبعة أيام ويُستهلك مرة واحدة. إعادة الدعوة تلغي الرمز السابق. يمكن إلغاء الدعوة، وتُلغى دعوات العضو عند تغيير دوره أو إزالته. الدعوات لا تنشئ حسابات ولا تمنح صلاحيات دون قبول.

الدفتر يعرض رصيده الكامل ومعاملات الدورة المختارة مع الوارد والمصروف واسم منشئ السجل. يوم بداية الدورة قابل للتعديل من 1 إلى 31؛ يُستخدم آخر يوم من الشهر عندما يكون الشهر أقصر. المعاملات والفواتير تدعم الإضافة والتعديل والحذف وفق الدور. الفاتورة المتكررة تذكير فقط ولا تُخصم تلقائيًا؛ يسجّل العضو مصروف السداد بنفسه.

المبالغ العائلية الجديدة تحفظ كأعداد صحيحة من الوحدات الصغرى (100 لكل وحدة)، بمنزلتين عشريتين وبحد أقصى مليار لكل معاملة. لا يمكن تغيير العملة إذا وجد سجل مالي؛ استخدم دفترًا آخر للعملة الأخرى. هذا التنفيذ مناسب للعملات المعروضة ذات منزلتين، وليس لعملات بثلاث منازل عشرية.

سجل النشاط متاح للمالك والمدير، ويعرض آخر 100 حدث وأسماء المنفذين والتوقيت. قاعدة البيانات تحتفظ بالأحداث السابقة؛ لا تحتوي الأحداث مبالغ أو ملاحظات مالية أو رموز دعوات. سجل النشاط داخلي وليس تدقيقًا خارجيًا مقاومًا لتعديل مسؤول قاعدة البيانات.

تحديثات العائلة ترسل إشعار تحديث دون بيانات عبر SSE الحالي للأعضاء. الشاشة تجلب snapshot مصرحًا به من جديد؛ مع تعطيل المزامنة أو انقطاعها يتوفر زر تحديث، وتُحدث الشاشة عند العودة إليها. لا تُخزن بيانات العائلة في localStorage ولا تُضاف عملياتها إلى طابور الدفتر الشخصي دون اتصال. عند فقد الاتصال يفشل الحفظ بوضوح وتحتاج إعادة المحاولة؛ لا يعرض التطبيق حفظًا محليًا على أنه حفظ مشترك.

التصدير JSON مقروء يشمل معاملات وفواتير وإعدادات الدفتر العائلي فقط، دون رموز أو كلمات مرور أو بيانات شخصية للأعضاء. الاستيراد للمالك والمدير، دمج حسب المعرف فقط، بعد تأكيد المستخدم. يجب تطابق العملة؛ كامل الطلب يحفظ داخل transaction واحدة أو يتراجع كله، ويحافظ التحديث على منشئ السجل الأصلي. لا يعيد الاستيراد عضويات أو دعوات أو سجل نشاط أو هويات منشئي السجلات الجديدة؛ السجلات المستوردة الجديدة تُنسب للمنفذ. لا يدعم حذف دفتر عائلي كامل أو استبدال سجلاته دفعة واحدة. حد الملف 2 ميجابايت، وحد المعاملات والفواتير 10,000 لكل نوع لكل عائلة؛ حتى 100 عضو و100 دعوة معلقة، و20 عائلة يملكها كل حساب.

## الحفاظ على الموجود

الجداول الشخصية `users` و`transactions` و`settings` و`recurring_bills` تبقى كما هي. جداول `families` و`family_members` و`family_invitations` و`family_transactions` و`family_bills` و`family_audit` إضافية، وترتبط بالمستخدمين الموجودين. لا تعديل لمعرفات أو مبالغ أو كلمات مرور الدفاتر القديمة. لا يُنشأ مستخدم وهمي لكل عائلة، ولا تُستخدم جلسة المالك لطلبات الأعضاء.

الإلغاء لمرة واحدة للرموز القديمة في مرحلة الأمان ما زال قائمًا؛ يلزم الدخول بكلمة المرور مجددًا بعد أول نشر. اختبر نسخة متسقة من قاعدة الإنتاج قبل النشر، وتحقق من سلامة الجداول والحسابات القديمة والدخول. اتبع [دليل نشر أساس الأمان](security-foundation-deployment.ar.md) لأخذ نسخة SQLite متسقة والرجوع، ولا تنسخ `.db` وحده أثناء التشغيل مع WAL.

## التحقق وما بقي

`npm run lint` و`npm test` يشغّلان البناء واختبارات الأمان والعائلات على قواعد مؤقتة. يغطي الاختبار عزل الشخصي/العائلة والعائلات المختلفة، ربط الدعوة وحذفها وانتهاؤها، الأدوار وتجاوز الصلاحيات، إزالة العضو ونقل الملكية، دقة المبالغ، الفواتير، تطابق العملة، rollback تحت خطأ SQLite فعلي، التصدير وسلامة إعادة التشغيل.

اُختبرت الواجهة محليًا في Chromium على عرض 390 و1280 بكسل: إنشاء عائلة وحفظ معاملة وفاتورة، إنشاء دعوة وقبولها في حساب ثانٍ، عرض تعديل سجلات المحرر فقط، وتحديث المشاركين تلقائيًا. نجح تحويل المحرر إلى مشاهد وإزالته أثناء فتح الصفحة؛ اختفت أدوات التحرير ثم بيانات العائلة. لم يوجد تجاوز أفقي على الجوال أو أخطاء React في هذه الرحلة. الاختبار على بيانات مؤقتة، وليس جهاز iPhone فعليًا.

هذا تنفيذ دفاتر عائلية أساسي قبل النشر العام. ما زال يلزم تحقق البريد واستعادته، استعادة كلمة المرور وحذف الحساب بأمان، تخزين آمن للجلسات بدل التخزين المحلي، WebAuthn فعلي، وضبط CORS/CSP وHTTPS والنسخ والمراقبة بحسب بيئة النشر. الرسوم البيانية والمساعد الصوتي وطابور العمليات دون اتصال الحاليون خاصون بالدفتر الشخصي؛ لا تنفذ العائلة تلك الميزات بعد. التصميم الموحد المستهدف لـworkspaces وتقسيم تفضيلات الشخص/الدفتر والترحيل الكامل للعملة الصغرى موثق لكنه لم يحل محل مخطط الدفتر الشخصي الحالي.
