# شريط Get ودليل تثبيت التطبيق

يظهر شريط صغير أعلى الموقع قبل الدخول وبعده، فيه الشعار وHappy Home وزر Get. الضغط يفتح مربعًا صغيرًا فيه ثلاث رسوم توضيحية وخطوات حسب الجهاز: iPhone/iPad أو Android أو الكمبيوتر. توجد أزرار لتغيير نوع الجهاز، والإغلاق بـ X أو Escape أو الضغط خارج النافذة، مع إعادة التركيز إلى Get. إخفاء الشريط يُحفظ على نفس المتصفح. لا يظهر داخل وضع التطبيق المثبت، ويختفي عند وصول إشعار اكتمال التثبيت.

على iPhone/iPad: Safari → مشاركة → إضافة للشاشة الرئيسية → تفعيل فتح كتطبيق ويب إن ظهر ثم إضافة. على Android: قائمة Chrome → تثبيت التطبيق/إضافة للشاشة الرئيسية → تأكيد. إذا أتاح المتصفح beforeinstallprompt، يظهر زر تثبيت مباشر داخل الدليل. الرسوم توضيحية صغيرة وليست صورًا من شاشة هاتف المستخدم؛ قد تختلف القوائم والإصدارات. لا يُستخدم كاش الحساب أو السيرفر لهذا الشريط ولا تُضاف طلبات دورية.

## الانتقال لاحقًا إلى المتاجر

حاليًا المتغيران فارغان، لذلك لا يوجد رابط متجر وهمي. عند نشر تطبيق حقيقي أضف في .env على السيرفر:

```
VITE_APP_STORE_URL=https://apps.apple.com/.../id...
VITE_PLAY_STORE_URL=https://play.google.com/store/apps/details?id=...
```

هذه أمثلة لصيغة الرابط وليست روابط تطبيق منشور. يقبل البرنامج HTTPS فقط على apps.apple.com مع معرف التطبيق، أو صفحة details على play.google.com مع package id. Docker Compose يمرر القيم إلى مرحلة البناء. أعد البناء بعد تعديلها: متغيرات Vite تُضمّن في ملفات الواجهة ولا تتغير بتشغيل الحاوية فقط. Get يفتح متجر نظام الجهاز عند وجود رابط صالح، وإلا يبقى دليل تطبيق الويب. الكمبيوتر يظل على دليل التثبيت من المتصفح.

الشريط الجديد يستبدل البطاقة القديمة الطويلة داخل لوحة الحساب. لا توجد تغييرات في البيانات أو المزامنة أو الصلاحيات. اختبارات الكشف عن iPad وروابط المتاجر، واختبار المتصفح للهاتفين والإخفاء ووضع standalone والدليل والتركيز موضوعة في tests/install-offer.*. لا تثبت هذه الاختبارات تثبيتًا فعليًا على iPhone أو وجود تطبيق منشور في المتجر.
