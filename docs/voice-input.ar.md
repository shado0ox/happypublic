# إصلاح الإدخال الصوتي

كان effect يعيد إنشاء SpeechRecognition عند كل إعادة رسم بسبب تغيّر triggerToast في الأب. أصبحت الجلسة ثابتة حتى يتغير نوع المعاملة، وزر الإيقاف يشير إلى الجلسة نفسها. تُلغى الجلسة وتُزال handlers عند مغادرة الشاشة. لا توجد إعادة إنشاء عمياء بعد فشل start.

رسائل مستقلة لرفض الصلاحية، عدم توفر الميكروفون، خطأ الشبكة، وعدم سماع كلام؛ وإزالة وصف «أوفلاين» لأن خدمة المتصفح قد تتطلب الإنترنت. الصوت لا يُسجل أو يُخزن بواسطة التطبيق، لكن المتصفح قد يرسله إلى خدمة التعرف التابعة له.

على الهاتف: افتح رابط HTTPS واسمح للموقع بالميكروفون. إن كانت الخدمة غير مدعومة أو تعذرت، افتح «الإملاء من لوحة المفاتيح أو كتابة الجملة»، اضغط الخانة ثم ميكروفون لوحة مفاتيح الهاتف وأملِ الجملة، واضغط «تحليل الجملة». راجع التفاصيل ثم استخدم زر الحفظ الحالي. توفر ميكروفون لوحة المفاتيح يعتمد على إعدادات الهاتف.

تحليل الأرقام يدعم الأرقام العربية والفارسية والكسور العربية، و«مية وعشرين» و«ميتين وخمسين» و«خمسة آلاف»؛ وتُرفض المبالغ السالبة. لا تعديل لقاعدة البيانات أو البيانات الحالية.

التحقق: 34 اختبارًا نجحوا، وTypeScript والبناء نجحا. اختبار Chromium يستخدم SpeechRecognition محاكى للتحقق من ثبات الجلسة والإيقاف والتنظيف ورسالة الشبكة؛ واختبر أيضًا غياب API وتحليل الإملاء النصي ثم حفظ المصروف. هذا لا يثبت أن خدمة التعرف أو إذن الميكروفون يعملان على هاتف المستخدم؛ يحتاجان تجربة فعلية هناك.
